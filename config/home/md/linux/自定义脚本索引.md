## 使用入口

大多数维护脚本已经通过 fish PATH 暴露，可以直接运行。包管理、桌面和媒体脚本通过 `~/.local/bin` 软链接运行。`check-battery` 已从 `~/scripts/desktop` 迁到 `~/scripts/maintenance`，`~/.local/bin/check-battery` 软链已指向新位置。

```bash
term-menu
cache-clean
paru-ui
check-battery
```

## check-battery

用途：读取 `upower` 暴露的第一个电池设备，显示型号、状态、电量、健康度、设计容量和实际满充容量。

```bash
check-battery
check-battery --help
```

依赖：

```bash
sudo pacman -S --needed upower
```

说明：

- 只读脚本，不会修改电源配置。
- 台式机、虚拟机或没有暴露电池的环境会提示“未检测到电池设备”。
- 健康度优先读取 `capacity` 字段；没有该字段时，用 `energy-full / energy-full-design` 计算。

## 桌面和媒体脚本

```bash
b23                       # 从剪贴板读取 B 站链接并播放
b23 'https://b23.tv/...'  # 直接播放传入的链接
niri-keys                 # 打开 kitty + fzf 快捷键搜索
niri-keys --print         # 直接打印解析结果，便于检查
hypr-keys                 # Hyprland 版：打开 kitty + fzf 快捷键搜索
hypr-keys --print         # 直接打印解析结果，便于检查
```

说明：

- `b23` 会清理 B 站链接里的常见跟踪参数，保留分 P、时间点等播放相关参数。
- `b23` 默认读取 Wayland 剪贴板；直接传 URL 时不需要 `wl-paste`。
- `niri-keys` 解析 `~/.config/niri/dms/keybinds.kdl`，默认打开搜索界面；`--print` 不进入 fzf，适合排错和文档核对。
- `hypr-keys` 是 Hyprland 版速查（`Super+/` 触发）。Hyprland 配置是 Lua 格式，故数据源改为独立清单 `~/.config/hypr/keybinds.list`（改键位后同步此清单；键位现拆分在 `~/.config/hypr/conf/keybinds.lua`）。脚本主体在 `~/scripts/desktop/hypr-keys`，另在 `~/.config/hypr/scripts/hypr-keys` 放一份副本、`~/.local/bin/hypr-keys` 建软链。
- `fake-overview.sh` 是 Hyprland 下的无插件伪概览（`Super+D` 触发）。主力布局是 scrolling（横向滚动），触发时临时把 `general:layout` 切成 dwindle 让当前工作区所有窗口平铺展开＝概览，监听到用户聚焦到不同窗口或切显示器后自动切回。依赖 `socat`。因 Hyprland 用 Lua 配置（non-legacy parser），运行时改布局用 `hyprctl eval 'hl.config({ general = { layout = ".." } })'`，不能用 `hyprctl keyword`。socat 用进程替换启动并配 EXIT trap 显式 kill，避免每次概览残留 socat。

## wf-recorder-menu / screenshot-sound（niri / Hyprland 通用）

来源：`SHORiN-KiWATA/shorin-dms-hyprniri`（`fake-overview.sh` 同源）。二者均是纯 wlroots 工具，合成器无关，niri 和 Hyprland 会话都能用。命令入口 `~/.local/bin/{wf-recorder-menu,screenshot-sound}` 软链到 `~/scripts/desktop/`。

```bash
wf-recorder-menu            # 打开录制菜单（toggle：未录则弹菜单，正在录则停止）
wf-recorder-menu start      # 直接开始（RECORD_MODE 环境变量可定全屏/区域）
wf-recorder-menu stop       # 停止并保存
wf-recorder-menu status-json  # Waybar 用 JSON 状态
```

- `wf-recorder-menu`：全屏 / 区域 / GIF 三种模式，菜单后端自动探测 `fuzzel > wofi > rofi > bemenu > fzf > 终端`。设置（编码器 libx264/VAAPI、帧率、音频、文件格式、渲染设备）持久化到 `~/.cache/wf-recorder-sh/`；运行时状态在 `$XDG_RUNTIME_DIR/wfrec/`。GIF 走 ffmpeg 两遍 palettegen/paletteuse 高质量抖动。停止后自动 `wl-copy --type text/uri-list` 把文件对象塞进剪贴板，可直接粘到文件管理器或聊天软件。录制到 `~/Videos/wf-recorder/`（全屏在 `fullscreen/` 子目录），并维护 `latest` 软链。依赖 `wf-recorder`、`slurp`（区域选择）、`ffmpeg`（GIF）、`wl-clipboard`。中/日/英三语随 `LANG`。
- `screenshot-sound`：常驻守护进程，`wl-paste --watch` 监听剪贴板出现 `image/*` 时播放快门音。为避免平时复制图片误响，采用“扳机”机制——只有先「上膛」（在 `/dev/shm/screenshot_sound_armed` 建触发文件），且 15 秒内出图才响，响后即删触发文件防连响。上膛方式是执行 `screenshot-sound arm` 子命令（早期用 `SIGUSR1` 信号，已废弃：守护进程被 niri `spawn-at-startup` / hypr `exec_cmd` 以非 tty stdin 启动时信号方案不可靠，改为直接写触发文件的子命令）。守护进程用 `flock` 单实例锁，重复自启不会产生竞争的多个 watcher。音效文件默认按候选列表探测（`camera-shutter.oga` 等，装 `sound-theme-freedesktop` 提供），可用 `SCREENSHOT_SOUND` 环境变量覆盖；触发文件路径和超时分别用 `SCREENSHOT_SOUND_TRIGGER`、`SCREENSHOT_SOUND_TIMEOUT` 覆盖。**已接入两个会话**：niri（`config.kdl` 里 `spawn-at-startup` 自启守护进程，`keybinds.kdl` 各截图键用 `spawn-sh` 先跑 `screenshot-sound arm` 再 `niri msg action screenshot*`）和 Hyprland（`~/.config/hypr/conf/autostart.lua` 的 `hyprland.start` 钩子自启，截图键 `arm_shutter` 前缀跑 `screenshot-sound arm`）。DMS 与 pngshot 截图默认都会把图写入剪贴板，故音效可正常触发；pngshot 钉图（pin-last）复用已有剪贴板图、不算新截图，故不上膛。
- `wf-recorder-menu`：两会话都绑 `Alt+F5`＝`wf-recorder-menu toggle`（合成器无关，niri 原有、Hyprland 已补齐）。
- 屏幕放大镜 `Alt+A`：niri 用 `wooz`（layer-shell 叠加，在 niri 上正常）；**Hyprland 改用 `hypr-magnifier`**——wooz 的 `wlr-screencopy` 覆盖层在 Hyprland 下缺 damage 追踪，鼠标一动就把自身覆盖内容反复截入，产生撕裂/拖影/“橡皮擦”残影，故 Hyprland 侧改用原生 `cursor:zoom_factor`（GPU 合成阶段缩放，不走截屏回环，默认跟随光标），单键循环 `1x→2x→3x→关`。运行时改配置走 `hyprctl eval + hl.config`（Lua parser 下 `hyprctl keyword` 不可用）；`~/.config/hypr/conf/appearance.lua` 已启用 `zoomFactor` 动画 leaf 做平滑过渡。`--reset` 直接归位 1x。
- fuzzel 弹框样式：`gsudo`、`fuzzel-askpass`、`quickload`、`wf-recorder-menu` 等脚本都用 `fuzzel --dmenu` 弹菜单，外观由 `~/.config/fuzzel/fuzzel.ini`（静态结构）+ `~/.config/fuzzel/colors.ini`（DMS matugen 动态配色）统一控制，配色随系统主题自动变。机制与踩坑见专题文档 `fuzzel美化与动态配色.md`。

## 包管理脚本

```bash
paru-ui                  # 打开 Pacman/AUR 搜索安装 TUI
paru-ui firefox          # 带初始搜索词打开
paru-ui -c package       # 只审查 AUR 包，不安装
paru-ui -y               # 清缓存后打开
pak                      # Flatpak 安装 TUI
pacd                     # 降级已安装包
pacr                     # 卸载 Pacman/AUR/Flatpak 包
pacrrr                   # 追踪并清理应用残留
```

`paru-ui` 使用本地索引缓存和预览缓存；索引缓存会在 pacman 同步库或已安装包状态变化后自动失效。官方仓库包不会走 AUR 审查提示词。AUR 审查提示词在：

```text
~/scripts/share/prompts/aur-review.md
```

## 维护检查脚本

```bash
cache-clean
cache-clean --safe
recommend-check
pacnew-check
log-check
check-battery
boot-check
gpu-check
hw-doctor
```

`cache-clean` 默认只列缓存体积，不删除文件；`--safe` / `--dev` / `--chrome` 才会按白名单清理用户缓存。`recommend-check` 会一次性读取已安装包列表后在内存判断缺失项；`hw-doctor` 会复用同一轮 `lscpu/lspci/lsmod` 输出，避免重复硬件查询。`log-check` 会把日志内容写入：

```text
~/log-check-YYYYMMDD-HHMMSS.md
```

## 快照脚本

```bash
quicksave
quicksave -l
quicksave -c root -del 123
quickload
quickload -l
quickload -n -c root
```

注意：

- `quicksave -del all` 会删除快照，执行前确认配置名。
- `quickload` 会恢复系统或用户目录快照，成功后通常会重启。
- 不确定快照内容时，先用 `quickload -l` / `quickload -la` 查看。

## 迁移脚本

```bash
migration-pack --pack
migration-pack --check
```

默认目录：

```text
~/migration-backup
```

`--pack` 会写入备份目录；`--check` 是只读校验。
