# 系统维护脚本使用说明

> 更新日期：2026-07-14  
> 适用环境：当前 Arch Linux + fish + kitty + fzf + DMS/Niri 桌面环境；登录管理器为 greetd + DMS greeter（已弃用 SDDM）。  
> 维护脚本目录：`~/scripts/maintenance`  
> 桌面/媒体脚本目录：`~/scripts/desktop`、`~/scripts/media`  
> 快速索引：`~/md/linux/自定义脚本索引.md`

## 1. 总览

这套脚本是个人系统维护工具，统一放在：

```text
~/scripts/maintenance/
├── term-menu
├── sysup
├── checkallupdates
├── clean
├── cache-clean
├── mirror-update
├── quicksave
├── quickload
├── hw-doctor
├── gpu-check
├── boot-check
├── recommend-check
├── pacnew-check
├── log-check
└── migration-pack
```

fish 配置中已经加入脚本目录：

```fish
fish_add_path -g ~/scripts/maintenance
```

因此在 fish / kitty 中可以直接运行：

```bash
term-menu
sysup
checkallupdates
clean
cache-clean
mirror-update
quicksave
quickload
hw-doctor
gpu-check
boot-check
recommend-check
pacnew-check
log-check

```

包管理、媒体和桌面脚本通过 `~/.local/bin` 软链接直接运行：

```bash
paru-ui
pak
pacd
pacr
pacrrr
b23
niri-keys
hypr-keys
wf-recorder-menu
screenshot-sound
hypr-magnifier
```

`check-battery` 原在 `~/scripts/desktop`，已迁入 `~/scripts/maintenance`（仍保留 `~/.local/bin` 软链），现在也在 fish PATH 里，可直接运行。

用途：

| 命令 | 作用 | 主要风险 |
|------|------|----------|
| `paru-ui` | Pacman/AUR 模糊搜索安装 TUI；`paru-ui -c` 只审查 AUR 包不安装，`paru-ui -y` 刷新缓存后打开 | 会安装软件；AUR 审查需要人工判断 |
| `pak` | Flatpak 应用模糊搜索安装 TUI | 会安装 Flatpak 应用 |
| `pacd` | 已安装包降级 TUI，调用 `downgrade` | 会回退软件版本 |
| `pacr` | Pacman/AUR/Flatpak 卸载 TUI | 会卸载软件 |
| `pacrrr` | 用 `strace` 追踪应用残留文件，选择后清理并可卸载软件 | 高风险，会删除选中的文件或目录 |
| `check-battery` | 读取 `upower` 的电池状态和健康度（已迁入 maintenance，统一 ui.sh 卡片风格） | 只读 |
| `b23` | 从剪贴板或传入参数提取 B 站链接，清理跟踪参数后用 `mpv` 播放 | 只读，会启动播放器 |
| `niri-keys` | 解析 Niri/DMS 快捷键配置，打开 `kitty + fzf` 搜索；`--print` 可直接输出 | 只读 |
| `hypr-keys` | 读取 `~/.config/hypr/keybinds.list`，打开 `kitty + fzf` 搜索 Hyprland 快捷键；`--print` 可直接输出 | 只读 |
| `wf-recorder-menu` | wf-recorder 屏幕录制菜单（全屏/区域/GIF），设置持久化，停止后写视频文件；合成器无关，niri/hyprland 通用 | 中，会写视频文件 |
| `screenshot-sound` | 截图音效守护进程；`wl-paste --watch` 监听剪贴板出现图片且已 `arm` 上膛时播放快门音（已接入 niri/hypr 截图键） | 只读，常驻后台 |
| `hypr-magnifier` | Hyprland 原生屏幕放大镜（`cursor:zoom_factor` 循环 1x→2x→3x→关，`Alt+A` 触发，`--reset` 归位）；仅 Hyprland，niri 仍用 `wooz` | 只读 |

`paru-ui` 的 AI 审查提示词位于：

```text
~/scripts/share/prompts/aur-review.md
```

这个提示词只用于 `paru-ui` 选中 AUR 包后的 PKGBUILD 审查；官方仓库包不会走这套提示词。缺少 `opencode` 或提示词时，`paru-ui -c` 不能执行审查，普通安装模式会提示并回到常规 AUR 安装流程。审查提示里输入 `m` 可以临时切换并记住 opencode 模型。

查询缓存：

```text
~/.cache/paru-ui/package-index.tsv      # paru-ui 包名索引缓存
~/.cache/paru-ui/previews/              # paru-ui 预览缓存
~/.cache/paru-ui/review/                # AUR 审查临时构建文件
~/.cache/pacd_tui/repo_packages.txt     # pacd 仓库来源映射缓存
~/.cache/pacr_tui/repo_packages.txt     # pacr 仓库来源映射缓存
```

`paru-ui` 使用本地包名索引和预览缓存；`Tab` 可多选，`Ctrl+R` 会重建索引和刷新预览，`paru-ui -y` 会先清缓存再打开界面。索引缓存会在 pacman 同步库或本机已安装包状态变化后自动失效，避免显示旧的安装状态。`pacd`、`pacr` 会在 pacman 同步库更新后自动刷新 repo 缓存。`pak` 列表和预览优先读 Flatpak 本地 AppStream 缓存，`pak -y` 会先刷新 AppStream。

### b23 / niri-keys / hypr-keys 用法

```bash
b23
b23 'https://b23.tv/...'
b23 'https://www.bilibili.com/video/BV...?p=2&t=60'
niri-keys
niri-keys --print
hypr-keys
hypr-keys --print
```

说明：

- `b23` 默认读取 Wayland 剪贴板；直接传入 URL 时不需要 `wl-paste`。
- `b23` 会保留 B 站播放相关参数，例如分 P 和时间点，丢弃常见跟踪参数。
- `b23` 通过 `mpv --ytdl-raw-options` 调用 `yt-dlp`，默认用 `cookies-from-browser=chrome` 读取浏览器登录态；如需换浏览器，设置 `B23_COOKIES_FROM_BROWSER`。
- `niri-keys` 默认进入交互搜索；`--print` 不依赖 `fzf` / `kitty`，适合检查解析结果。
- `hypr-keys` 是 Hyprland 会话下的对应工具（`Super+/` 触发）；解析 `~/.config/hypr/keybinds.list`，改键位（`~/.config/hypr/conf/keybinds.lua`）后同步该清单文件。

### check-battery 用法

`check-battery` 只读读取 `upower` 的第一个电池设备：

```bash
check-battery
check-battery --help
```

输出内容包括设备型号、当前状态、当前电量、电池健康度、设计容量和实际满充容量。虚拟机、台式机或没有暴露电池的环境会返回：

```text
[Error] 未检测到电池设备
```

健康度优先读取 `upower` 的 `capacity` 字段；如果没有这个字段，会用 `energy-full / energy-full-design` 计算。依赖缺失时安装：

```bash
sudo pacman -S --needed upower
```

### wf-recorder-menu / screenshot-sound 用法

两个脚本都与合成器无关，niri 和 Hyprland 会话通用；来源为 GitHub `SHORiN-KiWATA/shorin-dms-hyprniri`，本机已改到 lint 干净并放入 `~/scripts/desktop/`（命令入口软链在 `~/.local/bin`）。

```bash
wf-recorder-menu            # 无参数=toggle：未录制则弹菜单，录制中则停止
wf-recorder-menu toggle     # 同上，建议绑定到快捷键
wf-recorder-menu status     # 打印录制状态/计时
wf-recorder-menu waybar     # 输出 waybar JSON（text/tooltip/class/alt）
wf-recorder-menu settings   # 直接打开设置菜单
```

- 菜单项：全屏、区域、录制 GIF（区域）、设置、退出；后端自动探测 `fuzzel > wofi > rofi > bemenu > fzf > 终端`，本机用 fuzzel。
- 设置项（编码器 libx264/VAAPI、帧率、音频开关、文件格式、渲染设备）持久化在 `~/.cache/wf-recorder-sh/`；运行时状态在 `$XDG_RUNTIME_DIR/wfrec/`。
- 视频默认存 `~/Videos/wf-recorder/`（全屏在 `fullscreen/` 子目录，GIF 在 `gif/` 子目录），并维护一个 `latest` 软链；停止后自动把文件以 `text/uri-list` 塞进剪贴板，可直接粘到文件管理器/聊天软件。
- 依赖：`wf-recorder`、`slurp`（区域选择）、`ffmpeg`（GIF 两遍 palettegen/paletteuse）、`wl-copy`（剪贴板），均已安装。
- 状态栏计时靠 `RTMIN+9` 信号驱动 waybar；本机主力是 DMS/quickshell 而非 waybar，此项静默无副作用，`WAYBAR_POKE=off` 可关。

```bash
screenshot-sound            # 前台常驻守护进程（run 子命令等价），监听剪贴板
screenshot-sound arm        # 上膛：创建触发文件（截图键在抓图前调用这个）
```

- 机制：`wl-paste --watch` 监听剪贴板变化，出现 `image/*` 且已「上膛」时播放快门音。上膛＝存在 `/dev/shm/screenshot_sound_armed` 触发文件；须在 `TIMEOUT_SEC`（默认 15s）内出图才播音，响后即删触发文件防连响，避免平时复制图片误触发。`flock` 单实例锁防重复自启，0 CPU 常驻。
- 上膛用 `screenshot-sound arm` 子命令直接建触发文件（不再用早期的 `SIGUSR1` 信号方案——守护进程在 niri `spawn-at-startup` / hypr `exec_cmd` 下 stdin 非 tty，信号方案不可靠，已改为无信号的子命令 + 单实例锁）。
- 音效文件按候选列表自动探测（首选 `sound-theme-freedesktop` 的 `camera-shutter.oga`，已安装），可用环境变量 `SCREENSHOT_SOUND` 覆盖；触发文件路径 `SCREENSHOT_SOUND_TRIGGER`、超时 `SCREENSHOT_SOUND_TIMEOUT` 也可覆盖。
- **已接入两个会话**：守护进程随会话自启（niri `spawn-at-startup`、hypr `hyprland.start` 钩子）；截图键在抓图前先调 `screenshot-sound arm` 上膛。niri 每个键位只能绑一个动作，故用 `spawn-sh "…/screenshot-sound arm; niri msg action screenshot…"` 串起。DMS 自身不带快门音，不会重复。钉图（pin-last，粘贴已有剪贴板图）不上膛。

### hypr-magnifier 用法（仅 Hyprland）

Hyprland 会话专用的屏幕放大镜，绑定 `Alt+A`。命令入口软链在 `~/.local/bin`。

```bash
hypr-magnifier            # 无参数=循环 1x → 2x → 3x → 关
hypr-magnifier --reset    # 直接归位 1x（关闭放大）
```

- 为什么不用 wooz：niri 的 `Alt+A` 用 `wooz`（layer-shell 叠加）在 niri 上正常，但 wooz 的 `wlr-screencopy` 覆盖层在 Hyprland 下缺 damage 追踪，鼠标一动就把自身覆盖内容反复截入，产生撕裂/拖影/“橡皮擦”残影。故 Hyprland 侧改用原生 `cursor:zoom_factor`（GPU 合成阶段缩放，不走截屏回环，默认跟随光标 `cursor:zoom_rigid=false`）。niri 侧保留 wooz 不动。
- 运行时改配置走 `hyprctl eval "hl.config({ cursor = { zoom_factor = N } })"`（Lua non-legacy parser 下 `hyprctl keyword` 不可用）；`~/.config/hypr/conf/appearance.lua` 已启用 `zoomFactor` 动画 leaf 做平滑过渡。
- 从非会话 shell（如脚本调试）调用时脚本会自动补 `HYPRLAND_INSTANCE_SIGNATURE`；正常键位调用已带该环境变量。

运行：

term-menu

菜单项：

| 编号 | 名称 | 命令 | 作用 |
|------|------|------|------|

| 02 | 系统清理 | 内置分类 | 系统清理、用户缓存预览/清理 |

| 04 | 系统检查 | 内置分类 | 硬件、GPU、电池、引导、推荐补齐、pacnew、日志报告 |
| 05 | 迁移工具 | `migration-pack` | 进入后选择生成或检查迁移包 |

分类里的具体动作：

|------|------------|

## 3. 系统更新：sysup

用途：

- 读取 Arch Linux 新闻
- 可选创建 Btrfs 快照
- 检查镜像源新鲜度
- 同步 keyring
- 执行系统升级
- 更新 Flatpak
- 重新生成 GRUB 配置
- 更新 `checkallupdates` 缓存

常用命令：

```bash
sysup
sysup -l
sysup --news-source cn
sysup --count 10
```

说明：

- `sysup -l` 会先打开 `checkallupdates`。
- 系统升级使用 `paru -Su`，没有 `paru` 时尝试 `yay -Su`。
- 如果根分区是 Btrfs 且 `quicksave` 可用，会先创建 `quicksave-sysup` 快照。
- 如果 `/etc/pacman.d/mirrorlist` 超过 30 天，会询问是否运行 `mirror-update`。

风险点：

- 更新中断后不要直接 `pacman -S` 安装新包，必须重新完成系统升级，避免部分升级。
- `grub-mkconfig` 只在命令存在时运行。

## 4. 待更新列表：checkallupdates

用途：

- 用 `fzf` 查看待更新项目
- 支持 Pacman、AUR、Flatpak
- 支持缓存加速
- 支持 `Ctrl+R` 强制刷新
- 选中真实更新项按 `Enter` 后启动 `sysup`
- 没有待更新项目时显示“当前没有待更新项目”，按 `Enter` 不会启动更新

运行：

```bash
checkallupdates
```

刷新缓存：

```bash
checkallupdates --refresh
```

缓存目录：

```text
~/.cache/checkallupdates/
├── updates-repo.txt
├── updates-aur.txt
├── updates-flatpak.txt
└── last-refresh
```

依赖：

- `fzf`
- `checkupdates`
- `paru` 或 `yay`
- `flatpak` 可选

说明：

- `checkupdates` 只检查官方仓库更新。
- `paru -Qua` / `yay -Qua` 检查 AUR 更新。
- Flatpak 更新默认用 `flatpak remote-ls --updates --cached` 读取本地 AppStream，减少菜单打开时的联网等待。
- 需要强制让 Flatpak 更新查询走网络时，用 `CHECKALLUPDATES_FLATPAK_ONLINE=1 checkallupdates --refresh`。

## 5. 系统清理：clean

用途：

- 删除孤儿包
- 删除无主 `-debug` 包
- 清理 pacman / AUR 缓存
- 清理残留下载目录
- 清理 systemd journal
- 清理回收站、缩略图、剪贴板缓存
- 清理未使用 Flatpak runtime
- 清理旧 Btrfs 快照

常用命令：

```bash
clean
clean all
clean --yes
clean all --yes
```

普通 `clean`：

- 不清理截图和录屏目录
- 不完全清空所有包缓存
- 不删除所有快照，只执行 snapper 规则清理

孤儿包卸载行为（2026-07 修复）：

- 孤儿包卸载失败（依赖冲突，或在 pacman 确认时选 n）不会再中断整个脚本，会提示“已跳过”后继续执行缓存、日志、回收站、快照等后续清理步骤。

`clean all`：

- 完全清空包缓存和 AUR 源码缓存
- 清理截图和录屏目录
- 清理更多 Btrfs 快照

`clean all` 会清理这些媒体目录：

```text
~/Pictures/Screenshots
~/Videos/wf-recorder
~/Videos/shorin-screenrec-menu
```

风险点：

- `clean all` 是高风险模式，执行前确认截图、录屏、快照都不需要保留。
- `--yes` 会跳过确认，不建议日常使用。

## 6. 用户缓存清理：cache-clean

用途：

- 预览用户缓存体积
- 保守清理可重建缓存
- 单独清理开发缓存或 Chrome 缓存
- 避免误删 opencode 数据库、Mason 工具链、Rust 工具链、浏览器配置等状态数据

常用命令：

```bash
cache-clean
cache-clean --safe
cache-clean --dev
cache-clean --chrome
cache-clean --all-safe
```

默认 `cache-clean` 只列体积，不删除任何文件。真正清理时必须传 `--safe`、`--dev`、`--chrome` 或 `--all-safe`，脚本会先列体积和本次清理计划，再输入 `yes` 确认；`-y` / `--yes` 可跳过确认。

显示行为（2026-07 优化）：

- 只有默认 `cache-clean`（概览）会列出「可清理 / 系统级 / 保留不动」三组全景。
- `--safe`、`--dev`、`--chrome` 等清理模式只显示本次真正会清理的缓存，不再混列无关项，末尾统一提示不会动的状态数据。

风险点：

- `--dev` 会清 go-build、pip、npm cache，后续构建或安装可能重新下载/生成缓存。
- `--chrome` 会清 Chrome HTTP/Code/GPU 缓存，执行前最好关闭 Chrome。
- `cache-clean` 不清 `/var/cache/pacman/pkg`，系统包缓存继续用 `clean` 管。
- `cache-clean` 不清 `~/.local/share/opencode/opencode.db`、`~/.local/share/nvim/mason`、`~/.rustup`、`~/.cargo`。

## 7. 镜像源更新：mirror-update

用途：

- 使用 reflector 更新 pacman 镜像源
- 写入 `/etc/pacman.d/mirrorlist`
- 自动备份旧 mirrorlist

常用命令：

```bash
mirror-update
mirror-update -c China
```

备份位置：

```text
~/.cache/mirror-update/
```

风险点：

- 会写系统文件 `/etc/pacman.d/mirrorlist`。
- 如果更新后网络或同步异常，应从备份恢复 mirrorlist。

## 8. 快照创建：quicksave

用途：

- 为 Snapper 配置创建 Btrfs 快照
- 默认描述为 `quicksave`
- 支持多配置；当前系统会同时为 `root -> /` 和 `home -> /home` 创建快照
- 支持列出和删除快照

常用命令：

```bash
quicksave
quicksave -d quicksave-manual
quicksave -c root
quicksave -lc
quicksave -l
```

删除快照：

```bash
quicksave -c root -del 123
quicksave -c root -del all
```

依赖：

- `btrfs`
- `snapper`
- `awk`
- `pkexec` 可选，用于修复普通用户权限

风险点：

- `-del all` 会删除指定配置下的快照，执行前必须确认配置名。
- 如果只删除 `root` 或只删除 `home` 的快照，会造成两边恢复点不再成组对应。

## 9. 快照恢复：quickload

用途：

- 从 Btrfs / Snapper 快照恢复系统
- 支持 root / home / 全系统恢复
- 支持从普通系统或快照启动项中运行
- 成功后自动重启

当前系统的含义：

- `全系统恢复`：同时恢复 `/` 和 `/home`
- `仅恢复系统目录 (root)`：只恢复 `/`
- `仅恢复用户目录 (home)`：只恢复 `/home`

常用命令：

```bash
quickload
quickload -l
quickload -la
quickload -lc
quickload -c root
```

直接恢复：

```bash
quickload -n -c root
quickload -n
```

依赖：

- `btrfs`
- `snapper`
- `btrfs-assistant`
- `findmnt`
- `awk`
- `grep`
- `sudo` 或 `pkexec`

风险点：

- `quickload -n` 不指定 `-c` 时会尝试全系统恢复。
- 恢复成功后会自动 `reboot`。
- 不确定快照内容时，先用 `quickload -l` / `quickload -la` 查看。
- 从 GRUB 选择快照只是临时启动快照，不是永久回档；进入快照系统后仍需运行 `quickload`。

滚挂恢复完整流程见：

```text
~/md/linux/Btrfs快照与滚挂恢复流程.md
```

## 9.1 快照删除与时间线频率

`term-menu` 的“查看快照”会直接展示：

```bash
snapper -c root list
snapper -c home list
```

不再先选择配置，方便现场直接对照 root / home 两套快照。

`term-menu` 的“删除快照”支持多选：

- `Tab`：选中快照
- `Shift+Tab`：取消选中
- `Enter`：确认选择
- 输入 `delete`：执行删除

当前系统的自动时间线快照来自：

```bash
systemctl list-timers 'snapper*' --all
systemctl cat snapper-timeline.timer
```

当前 systemd 原始 timer 是：

```ini
OnCalendar=hourly
```

但本机已通过 override 改为：

```ini
OnCalendar=*-*-01/2 04:00:00
```

也就是每月从 1 号开始，每隔 2 天的 04:00 创建一次 timeline 快照。`root` 和 `home` 都开启了 `TIMELINE_CREATE=yes`。

如果只想保留更少的小时快照，可改 Snapper 保留数量：

```bash
sudo snapper -c root set-config TIMELINE_LIMIT_HOURLY=3
sudo snapper -c root set-config TIMELINE_LIMIT_DAILY=7
```

如果要调整生成频率，创建 systemd override：

```bash
sudo systemctl edit snapper-timeline.timer
```

写入：

```ini
[Timer]
OnCalendar=
OnCalendar=daily
```

然后重载：

```bash
sudo systemctl daemon-reload
sudo systemctl restart snapper-timeline.timer
systemctl list-timers 'snapper*' --all
```

常见频率示例：

```ini
OnCalendar=hourly
OnCalendar=*-*-* 08,20:00:00
OnCalendar=daily
OnCalendar=*-*-01/2 04:00:00
```

建议：如果磁盘只有 30G，不建议保留太多小时快照。当前 `home` 的保留策略比 `root` 更克制，避免用户缓存和浏览器数据撑满磁盘。

GRUB 快照菜单由 `grub-btrfs` 生成：

```bash
sudo grub-mkconfig -o /boot/grub/grub.cfg
sudo systemctl enable --now grub-btrfsd.service
```

GRUB 里只显示 root 快照，这是正常的；home 快照不能单独启动系统。

## 10. 硬件检查：hw-doctor

用途：

- 快速检查当前机器是否适合继续迁移
- 查看 CPU 厂商和微码包
- 查看 GPU、网络、音频、Btrfs、Snapper、桌面服务状态
- 提示缺失的诊断工具

运行：

```bash
hw-doctor
```

重点看这些结果：

- `MISS amd-ucode` / `MISS intel-ucode`：实机安装时应按 CPU 厂商补微码，只装其中一个。
- `MISS mesa-utils` / `MISS vulkan-tools`：不影响开机，但会影响 OpenGL / Vulkan 排障。
- `tuned inactive`：当前物理机首轮迁移按文档暂不启用，这是正常状态。
- `vmtoolsd active`：物理机不应该启用；`vmtoolsd inactive` 或 `not-found` 是正常状态。
- `sof-firmware 未安装`：如果实机声卡、麦克风异常，优先补这个包。

说明：

- `hw-doctor` 是只读检查脚本，不会改系统。
- 当前物理机已经补齐 `mesa-utils`、`vulkan-tools`、`nvidia-prime`、`smartmontools`、`btop`、`powertop`、`fwupd` 等诊断工具。
- 它不能替代安装流程，只用于判断“硬件、服务、诊断工具”有没有明显缺口。

## 11. GPU 检查：gpu-check

用途：

- 查看 PCI 显卡和内核驱动
- 检查默认 OpenGL / Vulkan
- 检查 NVIDIA 工具链
- 检查 `prime-run` 混合显卡路径

运行：

```bash
gpu-check
```

实机常见判断：

- `amdgpu` 出现在内核模块里：AMD 核显/独显驱动已加载。
- `nvidia-smi` 正常输出：NVIDIA 用户态工具和内核模块基本可用。
- `prime-run glxinfo -B` 正常输出：混合显卡独显启动路径可用。
- `vulkaninfo --summary` 失败：优先检查 `vulkan-tools`、Mesa/NVIDIA Vulkan 驱动和环境变量。

说明：

- `gpu-check` 是只读检查脚本。
- 没有 NVIDIA 硬件时，`nvidia-smi` / `prime-run` 缺失不是错误。
- 当前物理机是 AMD 核显 + NVIDIA RTX 4050 Laptop；应能看到 `amdgpu`、`nvidia`、`nvidia-smi` 和 `prime-run`。

- 检查 `/boot/grub/grub.cfg`、`/boot/grub/grub-btrfs.cfg`

boot-check

- 检查 `/etc`、`/boot`、`/usr/lib/sysusers.d`、`/usr/lib/tmpfiles.d` 里是否有 pacman 配置残留

## 14. 日志检查：log-check

用途：

- 生成 Markdown 日志报告到 `~/log-check-YYYYMMDD-HHMMSS.md`
- 汇总系统 failed unit
- 汇总用户 failed unit
- 汇总本次启动的 system journal error 日志
- 汇总本次启动的 user journal error 日志
- 给出第一个失败系统服务的 `systemctl status` 和 `journalctl -u` 查看提示

运行：

```bash
log-check
```

说明：

- `log-check` 是只读检查脚本，不会重启服务，也不会修改 systemd 配置。

## 15. 推荐补齐：recommend-check

用途：

- 根据当前系统状态列出还建议安装的工具
- 区分“必要、推荐、条件、可选”
- 给出可复制的 `sudo pacman -S --needed ...` 命令
- 不自动安装软件，不修改系统配置

运行：

```bash
recommend-check
```

重点看这些结果：

- `efibootmgr`：双系统实机上用于查看 UEFI 启动项，确认 Windows Boot Manager 和 Arch/GRUB 是否还在。
- `os-prober`：用于让 GRUB 探测 Windows，双系统现场比较关键。
- `shellcheck`：改维护脚本前跑静态检查，能提前发现常见 Bash 问题。
- `downgrade`：`pacd` 的版本回退工具。
- `strace`：`pacrrr` 追踪应用残留文件时需要。
- `upower`：`check-battery` 读取电池状态时需要。
- `smartmontools` / `fwupd`：实机长期维护用，一个看硬盘健康，一个看固件更新。
- `vulkan-tools`：让 `gpu-check` 能输出 Vulkan 摘要。
- `btop` / `powertop`：一个看资源占用，一个看笔记本功耗线索。
- `opencode-bin`：只作为 `paru-ui -c` / AUR 审查的可选提示项显示；它是 foreign/AUR 包，不会混进 `sudo pacman -S` 建议命令。

说明：

- 当前物理机是 AMD Ryzen 平台，CPU 微码基线是 `amd-ucode`。
- 脚本会先读取一次已安装包列表，再在内存中判断缺失项；不会对每个推荐项单独运行一次 `pacman -Qq`。
- 硬件解析使用 `LC_ALL=C` 固定字段名，避免中文 locale 下 CPU 厂商识别为 unknown。
- `sof-firmware` 是条件项，只有实机声卡、麦克风异常时才优先补。
- `flatpak`、`downgrade`、`strace`、`upower`、`blueman` 属于可选项；不用对应脚本或没有对应硬件时可以不装。
- `~/scripts/share/prompts/aur-review.md` 缺失时会提示；这个文件随 `~/scripts` 迁移。

## 16. 迁移工具：migration-pack

用途：

- 默认进入选择菜单，可选择生成迁移包或检查迁移包
- 生成当前系统迁移备份目录
- 导出显式包、foreign/AUR 包、systemd 启用服务
- 打包关键配置、脚本、文档和 `pkg-deps.html` 关系图
- 单独复制私有密钥配置，并限制权限
- 生成 `SHA256SUMS` 校验文件

默认交互运行：

```bash
migration-pack
```

直接生成：

```bash
migration-pack --pack
migration-pack --pack /run/media/$USER/U盘名/migration-backup
```

直接检查：

```bash
migration-pack --check
migration-pack --check /run/media/$USER/U盘名/migration-backup
```

默认输出：

```text
~/migration-backup/
├── pkglist-explicit.txt
├── pkglist-foreign.txt
├── system-enabled-units.txt
├── user-enabled-units.txt
├── tar-manifest.txt
├── pang-arch-configs.tar.gz
├── secrets/
│   ├── secrets.fish
│   └── opencode.json
└── SHA256SUMS
```

风险点：

- 选择“生成迁移包”会写入目标备份目录，默认是 `~/migration-backup`。
- 选择“检查迁移包”是只读检查。
- 输出目录不能放在 `~/.config`、`~/.local/share/fcitx5/rime`、`~/scripts` 或 `~/md` 里面，否则脚本会拒绝执行，避免把备份包自己打进压缩包。
- `secrets/` 里可能有 API key、token、私有 provider 配置，不要上传公网。
- 主压缩包会排除 `~/.config/fish/secrets.fish` 和 `~/.config/opencode/opencode.json`，这两个文件只放在 `secrets/` 里。

恢复时的基本顺序：

```bash
pacman -Qqe | sort > new-pkglist-explicit.txt
comm -23 pkglist-explicit.txt new-pkglist-explicit.txt
tar -xzf pang-arch-configs.tar.gz -C "$HOME"
chmod 600 ~/.config/fish/secrets.fish ~/.config/opencode/opencode.json
```

## 21. 常见问题

### term-menu 退出无效

应确认退出项使用内部动作 `__exit`：

```bash
rg "__exit" ~/scripts/maintenance/term-menu
```

### 联网工具里没有 nmtui 或蓝牙

`联网工具` 分类固定存在。里面的 `nmtui` 和蓝牙工具按当前环境自动显示。确认：

```bash
systemctl is-active NetworkManager
command -v nmtui
command -v bluetui bluetuith blueman-manager blueberry
```

### checkallupdates 不显示 AUR

确认 AUR helper 可用：

```bash
command -v paru
paru -Qua
```

### gpu-check 缺少 Vulkan 或 NVIDIA 命令

先区分“硬件不存在”和“工具没装”：

```bash
lspci -k | rg -i 'vga|3d|display|nvidia|amd|intel'
command -v vulkaninfo nvidia-smi prime-run
```

没有 NVIDIA 显卡时，缺少 `nvidia-smi` / `prime-run` 正常。实机有 NVIDIA 时再补：

```bash
sudo pacman -S --needed vulkan-tools nvidia-utils nvidia-prime
```

### migration-pack 生成后如何处理 secrets

`secrets/` 目录只给自己迁移用，不要传到公开仓库、公开网盘或截图里。复制到新系统后恢复权限：

```bash
chmod 700 ~/migration-backup/secrets
chmod 600 ~/.config/fish/secrets.fish ~/.config/opencode/opencode.json
```

### sysup 找不到 mirror-update

确认脚本目录在 PATH：

```bash
fish -lc 'command -v mirror-update'
```

### quicksave / quickload 找不到配置

确认 snapper 配置：

```bash
snapper list-configs
```

### quickload 恢复失败

先查看可用快照和 btrfs-assistant 映射：

```bash
quickload -la
sudo env -u DISPLAY -u WAYLAND_DISPLAY -u XDG_RUNTIME_DIR btrfs-assistant -l
```

不要在不清楚目标快照时使用 `quickload -n`。

### GRUB 快照菜单显示旧内容

GRUB 读取的是 `/boot/grub/grub-btrfs.cfg`，不是实时读取 `snapper list`。刷新并开启自动更新：

```bash
sudo grub-mkconfig -o /boot/grub/grub.cfg
sudo systemctl enable --now grub-btrfsd.service
```

### 从 GRUB 进入快照后没有永久恢复

这是正常的。GRUB 只是临时从快照启动系统。要永久恢复，进入快照系统后执行：

```bash
quickload
```

然后选择 `全系统恢复`。
