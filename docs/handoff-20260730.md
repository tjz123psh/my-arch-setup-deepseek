`--apply` retains component `--apply-official`/`--apply-config` and adds:

- one exact displayed module/package/config/stage plan;
- read-only package/config target prechecks;
- all applicable confirmations before run-state, sudo or config writes;

- failed core stage exit preservation and dependent-stage `skipped` status;
- final passed/failed/skipped/not-applicable report;
- private schema-1 atomic state and detailed mode-600 run log with terminal
  success/failure metadata;
- `--retry <module>` for the latest matching failed/interrupted plan;
- verification before a previously passed stage is skipped;
- `--rerun` for an intentional new run, while an identical normal completed
  apply is rejected.

Resume identity contains profile, mode, resolved modules and a SHA-256
fingerprint of `install.sh`, executable manifests and selected repository config
sources. Changed selection/source/code cannot silently resume. Retry is currently
stage-wide: the requested module identifies the failed stage, not per-file or
per-package rollback. Only `latest-run` is directly resumable; older run
folders remain evidence.

VM combined apply has an official-package stage and records user config as
`not-applicable`, so no config confirmation is required. An explicit attempt to
select an unavailable greeter module is rejected before run state or sudo; the
normal ASUS path does not select one.
